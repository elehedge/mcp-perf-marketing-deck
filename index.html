설치 가이드|5-Minute Setup

PATH 1

JSON 설정 파일 방식

Cursor · Windsurf · Gemini CLI

설정 파일에 MCP 서버 URL 추가 → OAuth 자동 시작

// Cursor — .cursor/mcp.json
{ "mcpServers": { "airbridge": {
    "url": "https://mcp.airbridge.io/mcp"
}}}

// Windsurf — ~/.codeium/windsurf/mcp_config.json
  "serverUrl": "https://mcp.airbridge.io/mcp"

// Gemini CLI — ~/.gemini/settings.json
  "httpUrl": "https://mcp.airbridge.io/mcp"
URL 추가 후 첫 요청 시 OAuth 인증이 자동으로 시작됩니다
PATH 2

UI 설정 방식

Claude · ChatGPT

설정 화면에서 URL 입력 — JSON 편집 불필요

// Claude Desktop & Web (Pro+)
Settings → Connectors → "Add custom connector"
  URL: https://mcp.airbridge.io/mcp
  Advanced: OAuth Client ID / Secret

// ChatGPT (Plus+ / Business / Enterprise)
Settings → Apps → Developer Mode → "Create app"
  URL: https://mcp.airbridge.io/mcp
  ⚠ OAuth 2.1 + PKCE 필수 (Bearer 직접 불가)
Claude: Connectors 디렉토리에서 원클릭 설치도 가능

PART 5 STRUCTURE

MCP의 한계|"MCP is DEAD" 논란

MCP는 강력하지만, 구조적 한계도 존재한다. 개발자 커뮤니티에서 제기되는 핵심 이슈들

💥 컨텍스트 소비 문제

MCP 서버를 연결하면 도구 설명(Tool Description)이 AI의 작업 공간(컨텍스트 윈도우)을 차지합니다

5개
MCP 서버 연결
1/3
작업 공간 증발

⚠ 기타 이슈

속도 저하 — 매 요청마다 도구 목록 전송, 응답 지연
인증 반복 — 세션 만료 시 재로그인 필요
보안 우려 — 제3자 MCP 서버의 데이터 처리 신뢰성
환각 리스크 — AI가 도구를 잘못 호출할 가능성
🍔 레스토랑 비유

MCP는 식당에 10개의 메뉴판을 펼쳐놓는 것과 같습니다. 메뉴를 읽는 데만 시간이 가고, 정작 요리할 공간이 부족해집니다. 연결만 많다고 좋은 것이 아닙니다.

"잘 연결하는 것"보다 "잘 가르치는 것"이 더 중요할 수 있다

대안 기술들|Skills, API, A2A, CLI

ALTERNATIVE 1

Skills / Prompts

도구 연결 대신 AI에게 작업 방법을 가르침. 컨텍스트를 훨씬 적게 소비

비유: 메뉴판 대신 도서관 사서
컨텍스트 절약

Direct API Integration

플랫폼 종속적 — 호환성 없음
직접 연결
표준 아님

초기 단계

엔터프라이즈 거버넌스
* 엔터프라이즈 거버넌스: 기업 환경에서 요구되는 통제 체계 — OAuth 인증, 권한 관리(RBAC), 도구 호출 감사 로그, 입력값 검증 등. "누가, 언제, 어떤 데이터에 접근했는지" 추적 가능해야 하는 요건.
  CLI에도 인증을 붙일 수 있지만(gh auth, aws configure 등), CLI마다 인증 방식이 제각각이고 도구 단위 권한 제어와 구조화된 감사 로그를 별도로 구축해야 합니다. MCP는 이를 프로토콜 스펙 레벨에서 표준화하므로 CLI 10개의 거버넌스를 따로 만드는 것보다 관리 비용이 낮습니다.

MCP가 진짜 빛나는 순간|When MCP Shines

모든 상황에 MCP가 최선은 아닙니다. MCP가 진짜 필요한 경우를 알아야 합니다

✓ MCP가 적합한 경우

실시간 데이터가 필요할 때
"어제 캠페인 ROAS?" → 최신 데이터 직접 조회
복수 시스템 연결이 필요할 때
Airbridge + Slack + 스프레드시트 연동
표준 호환이 중요할 때
한 번 구축으로 Claude, ChatGPT, Cursor 모두 지원

✗ MCP보다 다른 방법이 나은 경우

정적 지식 전달
가이드, 매뉴얼 → Skills/Prompts가 더 효율적
단순 반복 작업
정해진 포맷 리포트 → 자동화 스크립트가 더 적합
컨텍스트가 제한적일 때
긴 대화 → 도구 설명이 공간 차지, 성능 저하
핵심: MCP + Skills + Direct API를 상황에 맞게 조합하는 것이 최선의 전략
